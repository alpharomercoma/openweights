# The 2026-09-05 sweep: commands, compiled models, canvas, and reading a page

Five things were asked of the build on a Qualcomm Device Cloud SM8650 (Snapdragon 8 Gen 3,
Android 14): that every slash command does what it says, that ExecuTorch models are seen
and usable and fast enough to be worth the download, that the three canvas artifacts are
actually buildable and actually render, and that a fetched page reaches the model as
content rather than as markup. The date finding has its own write-up in
[date-in-the-prompt.md](date-in-the-prompt.md).

Two real defects came out of it, plus one more from handing the change to `agy`.
Everything else held.

## Slash commands

Nine commands: `/new`, `/compact`, `/retry`, `/plan`, `/auto`, `/ask`, `/yolo`, `/goal`,
`/deep-research`.

Parsing was already covered thoroughly and the palette path was covered by `ComposerTest`.
What nothing covered was the join: the path a *typed* message takes, which is the path the
original bug took when "/plan" reached the model as a question. `EverySlashCommandEndToEndTest`
now walks it per command (the text, `submit`'s decision, the dispatch, and the action that
comes out), driven off `entries` so a tenth command is covered the day it is added. It also
pins the two properties a keyboard makes easy to break: autocapitalisation with a trailing
space still runs, and `/plan the trip` stays a sentence rather than becoming a mode change.

All nine pass.

## ExecuTorch

Both compiled models pushed to the phone are seen, load, and answer. `ExecuTorchOnDeviceTest`
is 7 of 7 against `Qwen3-1.7B-INT8-INT4-ExecuTorch-XNNPACK`: it opens, answers legibly,
reports what a second turn costs, still answers with reasoning off, reuses the warm head,
stops mid-reply, and reports a reply cut for budget.

Speed and quality against the closest GGUF twin, same phone, same four GSM8K prompts,
greedy:

| runtime | model | prefill | decode | correct |
| --- | --- | ---: | ---: | ---: |
| ExecuTorch | Qwen3-1.7B INT8-INT4 XNNPACK | 186 tok/s | **33.8 tok/s** | 4/4 |
| llama.cpp | Qwen3-1.7B Q8_0 | **371 tok/s** | 26.7 tok/s | 4/4 |

Nothing was changed here. It works.

### The viewers, measured rather than asserted

Both viewers make a layout promise and neither promise had ever been checked against a
browser. They can be: each writes what it laid out to `window.__ow`. Serve
`core/tools/src/main/assets/canvas` with the `__OW_*` placeholders filled in, load
`deck.html` and `doc.html`, read the hook, then walk every element and compare its right
edge against its page's.

**The deck keeps its promise.** A deliberately overlong slide reported
`fits: [1, 1, 0.613]`: scaled to 61% to fit the 1280x720 stage, which is what a presenter
would do by hand. Nothing clipped, nothing off the edge.

**The document did not.** A bare URL hung **73pt off the right of the A4 page**, with no
scrollbar to reach it and nothing on screen saying so. `pre` and `table` carried
`word-break: break-word` and prose and links carried nothing, so the URL set the minimum
width of the paragraph containing it. A long URL is the commonest long token in anything a
model writes.

Fixed with `overflow-wrap: anywhere` on the body and on links. Re-measured on the same
hostile document (a long unbroken token, a wide code block, a five-column table, a long
URL), zero elements overflow across three pages, and the page does not scroll sideways.

`CanvasViewerTest` pins the rules both promises rest on, since each is one tidy-up away
from silently going, and records the browser method for re-measuring.

## Reading a web page

**What the model receives is prose.** `readable()` takes the main content, drops the
furniture (`script`, `style`, `nav`, `footer` and friends) and strips the tags, then
decodes entities. A test now proves it on a realistic page: no tags, no stylesheet, no
script body, no navigation, and the sentence intact.

**What it could not do was look.** `fetch_url` returned the first 4,000 characters of a
page and nothing else. For a reference page, a changelog, or a table of specifications,
which is most of what is worth fetching by address, the answer is not in the opening, and
the model's only recourse was `save_to` plus a script, which is two more round trips and a
sandbox on a phone.

So `fetch_url` takes a `find` parameter now: a word, a phrase, or a regular expression.
The search runs against the whole downloaded page rather than the excerpt, and what comes
back is the matching passages with 300 characters around each, merged where they overlap,
capped at twelve matches and 4,000 characters.

Three things it has to survive, because the pattern is written by a language model:

- **A pattern that does not compile.** A model asked to find C++ writes `C++`, which is a
  syntax error and also obviously a literal. Anything that will not compile is searched for
  as plain text.
- **A pattern that never finishes.** `java.util.regex` backtracks and has no timeout;
  `(a+)+b` against a page of a's does not finish this century. The matcher reads its input
  through a `CharSequence` that throws once a 750 ms budget is gone, which is the only
  interruption point a backtracking matcher offers. Measured: it returns.
- **A pattern that matches everything.** Capped in both directions, matches walked and
  characters returned, because either one unbounded is the whole page again.

A search that finds nothing is reported as a fact about the page, with its length, so the
model can choose between a looser pattern and reading the page whole. A bare "not found"
was being reported to the user as "the page does not mention it", which is a different and
sometimes wrong claim.


## Reviewed by agy

`tools/review/agy_changes.py` is the session-shaped sibling of `agy_review.py`: it bundles
the files one change touched, with their tests, and sends them to `gemini-3.8-flash-medium`
in one pass instead of reading the codebase by area for an afternoon. Sixteen findings
across three bundles. Every one is a claim to verify, not a bug.

**Confirmed and fixed.** `CanvasServer.shellResponse` escaped `\`, `"` and `<` before
dropping a file name between the quotes of `var FILE = "..."`, and not line terminators.
The name arrives percent-decoded from a query parameter, so `%0A` is a real newline, and a
newline inside a JavaScript string literal is a syntax error that stops the viewer's whole
script: a blank canvas, with the reason only in a console nobody is reading. It is also
where a name the model chose reaches a script context. Now escaped properly, with a test
that drives a payload through the real server and checks it stays inside the literal.

**Confirmed and deferred.** `PromptDay.pinned` is one value for the whole process, but the
promise in its own documentation is per conversation. Tapping New Chat after midnight moves
the pin, and a conversation started yesterday that is later rebuilt from its transcript
gets today's date, diverging from the bytes its cache holds. It costs one prompt re-read,
once, in a narrow window. The fix is a day stored per conversation, which is a schema
change and does not belong in this commit.

**Refuted.** `runBlocking` inside the canvas server's four-worker pool was reported as a
deadlock. `Workspace.resolve` dispatches to `Dispatchers.IO` itself rather than to the
limited view, so the inner work draws from the full pool while the worker's thread is
blocked; the existing ten-connection test is the empirical half. The rest were either
against unchanged code that carries its reasoning in place (`ModelDownloader.adoptExisting`
deletes and adopts exactly as its own comments argue) or could not be grounded: a
`/data/data` against `/data/user/0` path mismatch needs a way for the two forms to arise in
this app, and neither the reviewer nor a second reading found one.
